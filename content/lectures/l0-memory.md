# 把显存拆成能核对的账

## 0 速览

用可执行数组实验核对把显存拆成能核对的账。容量上限8GB【文献：用户机器规格】，GPU可用量要扣除桌面与驱动。


## 1 心智模型

先写输入输出契约，再列存储与运算账，最后对比本机观测。把每一次测量当成模型检验：如果单位不一致，差异比值没有意义。先用1个小数组【估算：最小复现策略】验证，再扩大形状。


## 2 概念逐条


### 单位与权重

定义：显存账以字节为单位，参数量乘每元素字节数得到裸权重。

后果：把十进制GB当成GiB会高估可用空间。8【估算：本课程示例输入设定】GB=7.45GiB【估算：8×10^9/2^30】，驱动与桌面仍需另扣。

数学：符号表：P是参数数，b是每参数字节数，W是权重字节数。W=P×b。

工程后果：随机模型0.5B【估算：500000000参数】以FP16存储时，权重0.93GiB【估算：500000000×2/2^30】；这是裸权重，不含激活。

常见误解：以为模型文件小就能训练→实际梯度、优化器状态与临时张量也占空间。


### KV缓存

定义：每层注意力把历史token的K与V保留下来，缓存随序列长度线性增长。

后果：忽略KV会让长对话在权重能装下时仍然OOM；上下文加倍使缓存也加倍。

数学：符号表：L为层数，T为token数，H为KV头数，D为头宽，b为字节数。KV=2【估算：按本段符号定义展开】×L×T×H×D×b。

工程后果：取L=24【估算：本课程示例输入设定】、T=1024【估算：本课程示例输入设定】、H=8【估算：本课程示例输入设定】、D=64【估算：本课程示例输入设定】、b=2【估算：代入KV公式】，缓存48MiB【估算：2×24×1024×8×64×2/2^20】。GQA应填KV头数而非查询头数。

常见误解：以为KV只与参数量有关→实际批量、上下文和KV头数共同决定缓存。


### 训练状态

定义：训练账必须按权重、梯度、优化器状态、激活、工作区逐项列出。

后果：只算权重会遗漏Adam状态；FP32训练常驻项约为权重的四倍，激活还未计入。

数学：符号表：P是参数数；纯FP32 Adam常驻字节M=16【估算：按本段符号定义展开】×P，来自权重、梯度与两份状态。

工程后果：0.5【估算：本课程示例输入设定】B模型常驻约7.45GiB【估算：16×500000000/2^30】，在8【估算：本课程示例输入设定】GB机器上无激活余量；先用0.01【估算：本课程示例输入设定】B随机模型，常驻约0.15GiB【估算：16×10000000/2^30】，再测峰值。

常见误解：以为混合精度总是只要半份内存→实际是否保留主权重取决于优化器实现。

## 4 代码

```python
def kv_bytes(layers, tokens, heads, head_dim, item_bytes):
    return 2 * layers * tokens * heads * head_dim * item_bytes

assert kv_bytes(24,1024,8,64,2) == 50331648
```

## 5 边界与失败模式

先测空维度、常数行与大幅值输入；拒绝非有限值。若出现OOM，先将批量或上下文减半，再重新列出峰值账。内存限制256MiB【估算：CPU验收进程预算】不等于显存容量。

## 6 三分钟复述稿

裸权重、KV、训练状态分开记。半精度五亿参数裸权重约0.93GiB【估算：参数×字节】。示例KV为48MiB【估算：双缓存公式】。纯单精度Adam常驻约7.45GiB【估算：每参数十六字节】，所以先缩小随机模型再测峰值。
